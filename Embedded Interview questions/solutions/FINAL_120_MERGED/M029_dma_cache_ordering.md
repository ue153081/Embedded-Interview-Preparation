## Step 0 — What the interviewer wants

You won't corrupt buffers when CPU and DMA share RAM.

## Step 1 — Core answer (bullets)

- CPU wrote buffer → clean cache before DMA TX
- DMA wrote buffer → invalidate before CPU read
- DMB: memory access ordering between observers
- DSB: wait for all memory ops to complete
- ISB: flush pipeline after MMU/MPU change

## Step 2 — Traps / mistakes

- DMA into stack
- Forgetting invalidate on RX
- Using cached buffer without alignment

## Step 3 — Follow-ups with answers

**Q: Example DMB?**  
**A:** Publish descriptor chain: write descriptors, DMB, then kick DMA engine.

**Q: Coherent allocation?**  
**A:** dma_alloc_coherent or MPU non-cacheable alias.

## Step 4 — 60-second script

DMA and CPU don't see the same bytes unless you manage cache. Before TX I clean the buffer so memory has fresh data. After RX I invalidate before the CPU reads. On ARM, DMB orders stores before kicking hardware; DSB completes everything; ISB after changing MPU regions.

## Step 5 — TI story hook

PRU shared buffer needed explicit cache clean/invalidate on AM335x — missing clean caused stale TX CRC failures.
