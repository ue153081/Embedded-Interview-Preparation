## Step 0 — Clarifying questions

- Log to UART, flash, or both?
- Max log rate in fault storm?

## Step 1 — Requirements

- Async log ring; drop on full with counter
- SW timer service on HW tick
- Per-task heartbeat slots; outer WDT
- Fault manager FSM: detect→classify→act

## Step 2 — ASCII block diagram

```
  Tasks --> log_ring --> drain task --> UART / flash
  Tasks --> heartbeat --> WDT supervisor
  Faults --> fault_mgr --> retry | degrade | reset
```

## Step 3 — Components / APIs

- `log_printf(level, fmt)` macro → ring
- `timer_service_post(delay, cb)`
- `wdt_supervisor_kick()` after all heartbeats
- `fault_report(code, severity)`

## Step 4 — Failure modes

- Log flood hides real fault — rate limit
- Missed heartbeat — safe state
- Flash log wear — circular sector with metadata

## Step 5 — Tradeoffs table

| Timer struct | Insert | Cancel |
|---|---:|---:|
| Sorted list | O(n) | O(n) |
| Min-heap | O(log n) | O(log n) |
| Wheel | O(1) | O(1) coarse |

## Step 6 — Numbers / budgets

- Log ring 4 KB → ~200 lines at 20 B avg; drain at 115200 ~44 ms worst case

## Step 7 — Follow-ups

**Q: Crash persistence?**  
**A:** `.noinit` ram console or flash ring with magic header.

**Q: Fault degrade?**  
**A:** Retry N times with backoff, then limp mode or reset subsystem.

## Step 8 — TI story hook

Field drive logs: ramconsole survived WDT reset; fault_mgr downgraded to speed-limited mode after repeated encoder faults.
