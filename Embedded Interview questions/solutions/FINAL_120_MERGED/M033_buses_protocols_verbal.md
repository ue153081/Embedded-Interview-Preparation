## Step 0 — What the interviewer wants

Protocol-level reasoning beyond register poking.

## Step 1 — Core answer (bullets)

- I2C: open drain, START, addr+W/R, data bytes, ACK, STOP; clock stretch
- CAN: wired-AND arbitration — lowest ID wins; error frames escalate to bus-off
- Endian: define wire format explicitly; never assume struct layout matches wire

## Step 2 — Traps / mistakes

- Missing pull-ups on I2C
- Ignoring bus-off recovery
- Casting packet buffer to struct

## Step 3 — Follow-ups with answers

**Q: CAN bus-off?**  
**A:** Controller stops transmitting after error threshold — needs init recovery sequence.

**Q: Prevent endian bugs?**  
**A:** read_be16/write_le32 helpers; static_assert on wire struct sizes.

## Step 4 — 60-second script

I2C is open-drain with START, address, data, ACK, STOP — slaves can stretch SCL. CAN arbitrates by ID on the wire; too many errors trigger bus-off. I always use explicit endian helpers — ARM is little-endian, many protocols are big-endian.

## Step 5 — TI story hook

Host tool sent big-endian length field; firmware read as native LE — classic off-by-256 framing bug caught with hex dump.
