## Step 0 — What the interviewer wants

Systematic bench methodology, not guesswork.

## Step 1 — Core answer (bullets)

- ISR latency: DWT cycle counter or GPIO toggle + scope
- Jitter: histogram many samples; look for priority blocking
- Intermittent CRC: capture raw bytes, compare against golden; check endian
- printf changes timing — use trace buffer or deferred log

## Step 2 — Traps / mistakes

- Optimizing away variables when debugging
- printf in ISR
- Single-sample latency claims

## Step 3 — Follow-ups with answers

**Q: APEC methodology?**  
**A:** Define measurement window, trigger, and statistical report — mean and max jitter.

**Q: Heisenbug from debug?**  
**A:** Debug build disables optimizations; use -O2 with guarded trace macros.

## Step 4 — 60-second script

I measure ISR latency with cycle counters or a scope on a GPIO strobe. For intermittent bugs I log raw frames to a ring and post-process — never printf in the hot path. printf adds mutex and UART time that masks races.

## Step 5 — TI story hook

EnDAT timing failures only appeared at full speed — scope on SCK vs DATA pin showed setup violation; printf had been masking it by slowing the loop.
