## Step 0 — Clarifying questions

- End-to-end latency target?
- Who owns buffer lifetime across DMA complete?

## Step 1 — Requirements

- ISR enqueues events only; task parses
- DMA desc chain with completion callback
- Pipeline stages: acquire → process → release
- Power: quiesce DMA before sleep

## Step 2 — ASCII block diagram

```
  Sensor -> IRQ -> ring -> task -> filter -> alert
                |

                |
            process half -> release desc
```

## Step 3 — Components / APIs

- SPSC ring ISR→task
- `dma_chan_submit(desc, cb)`
- Pipeline stage function pointers
- pm: wait TX drain + DMA idle before WFI

## Step 4 — Failure modes

- Ring overflow — throttle source
- DMA error bit — teardown and reinit channel
- Sleep with active DMA — data corruption

## Step 5 — Tradeoffs table

| Stage | Latency | CPU |
|---|---:|---:|
| IRQ byte | low | high |
| IRQ + ring | medium | medium |
| DMA ping-pong | lowest bulk | low |

## Step 6 — Numbers / budgets

- Example: 10 kHz sample → 100 µs period; ISR budget 5 µs; task WCET 30 µs

## Step 7 — Follow-ups

**Q: Backpressure?**  
**A:** High-water callback throttles producer before drop.

**Q: DMA ownership?**  
**A:** CPU owns until submit; device owns until completion IRQ; then callback returns to pool.

## Step 8 — TI story hook

EnDAT path: PRU DMA ping-pong into cache-aligned buffers, R5F parses in task — IRQ only flipped buffer index.
